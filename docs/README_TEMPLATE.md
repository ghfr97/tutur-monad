# TUTUR

**Verifiable micro-bounties for local-language data.** Sponsors fund tasks, contributors submit language examples, validators review them, and accepted work is paid through smart contracts on Monad.

> Hackathon prototype for Monad Testnet. Testnet MON is not real-money revenue. Not production-ready.

## What it does

1. A sponsor funds a data task with native MON.
2. A contributor submits a text contribution and acknowledges the task usage terms.
3. Three validators review it; two matching votes decide acceptance or rejection.
4. On acceptance, the contributor receives the reward and treasury receives an 8% service fee.
5. On rejection or unresolved expiry, the sponsor receives a refund.

Raw text stays off-chain. The contract records a content hash and payment/verification state.

## Why Monad

Each task has its own escrow contract. Independent tasks do not need to update a single shared payout queue. This is an architectural fit for exploring Monad's execution model, not a claim that all transactions are guaranteed to run in parallel.

## Revenue hypothesis

The initial hypothesis is an 8% service fee on accepted work. A 1 MON reward would create a 0.08 MON fee. This is an illustrative testnet example, not validated pricing or proven revenue.

## Deploy

1. Create a fresh burner wallet and obtain testnet MON.
2. Deploy the factory to Monad Testnet. The human operator signs deployment.
3. Configure treasury and three distinct validator addresses.
4. Verify source on the explorer if available.
5. Set the public factory address in frontend configuration and redeploy.
6. Test create → submit → two votes → payout, then test rejection/refund if time permits.

## Limitations

- Hackathon prototype, not audited.
- Three trusted validators are configured for the demo; collusion and Sybil resistance are not solved.
- Human validators determine language quality.
- Contributor terms require legal review before production.
- Market demand and the 8% fee are hypotheses.
